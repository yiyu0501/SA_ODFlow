# ODFlow 評審 Q&A

## 1. 這跟一般文件管理系統有什麼不同？

ODFlow 不只是存檔系統，而是把文件生成、版本管理、ODF 原始檔保存、評鑑完整度檢核與 PDF 評鑑上傳包輸出串成一套流程。一般文件管理系統常常只負責放檔案，ODFlow 則更強調社團日常行政與評鑑場景。

## 2. 這跟 Notion / Google Drive 有什麼不同？

Notion 和 Google Drive 比較偏通用協作工具。ODFlow 則是針對學生社團文件流設計，內建評鑑分類、文件狀態、版本、ODT / PDF 匯出、評鑑 ZIP 輸出與 ODF 原始檔備份，目標更聚焦。

## 3. 為什麼這算 ODF 應用？

因為系統不是只把檔案轉成 ODF，而是讓 ODF 原始檔在平時就被建立、保存、管理與再利用。ODT / ODS 範本庫、ODF 匯出、ODF 原始檔備份 ZIP，都是把 ODF 真正放進使用流程裡。

## 4. 為什麼不是只做 PDF？

PDF 適合提交與閱讀，但不適合持續維護。學生社團真正需要的是可編輯、可延續、可交接的原始檔，所以系統平時保留 ODF 原始檔，評鑑時再輸出 PDF。

## 5. AI 在裡面扮演什麼角色？

目前 AI 的角色非常有限，主要是會議紀錄流程中的 mock parser 概念展示。作品的核心價值仍在文件流設計、ODF 保存、評鑑輸出與資料完整度管理，不是完全依賴 AI。

## 6. 目前有沒有真的串 OpenAI API？

沒有。目前系統沒有直接呼叫 OpenAI API，會議紀錄生成使用的是 mock parser。

## 7. 這個系統的可行性如何？

可行性高，因為目前系統已可本機執行，具備多文件生成、文件庫、版本管理、ODT / PDF 匯出、Dashboard、Evaluation ZIP 輸出與 Templates 範本庫，不是只有概念稿。

## 8. 學生社團真的會用嗎？

有機會，因為它切的是社團最常見的痛點：會議紀錄、活動企劃、成果報告、年度計畫、評鑑整理。這些都不是少數需求，而是多數社團都會遇到的行政工作。

## 9. 這個工具如何推廣 ODF？

它不是要求使用者先理解 ODF 理念，而是先提供範本、匯出與流程價值。使用者在實際用過後，會自然理解 ODF 原始檔保存的重要性，這比單純宣傳格式更有效。

## 10. 目前限制是什麼？

目前沒有 OpenAI API、音檔轉文字、Google Drive 自動上傳、登入系統、多使用者權限，也還沒有完整 Projects 管理。這一版定位是展示型 MVP。

## 11. 如果學校評鑑規則不同怎麼辦？

目前系統的七大分類與規則是以臺北市立大學社團評鑑為基礎。未來可把 required documents、分類名稱與 ZIP 輸出規則做成可調整設定，以適配不同學校。

## 12. ODT / ODS 範本品質目前到哪裡？

目前已升級到較正式、可列印、可提交的校園社團文件風格。核心範本已具備標題、基本資料表、章節分段與清楚表格，足以支援日常行政與評鑑整理；但它仍不是高美編設計版，後續還可再精修欄寬、版面與更多真實使用情境。

## 13. 為什麼要有 ODF 原始檔備份 ZIP？

因為 PDF 是提交格式，但 ODF 原始檔才是長期可編輯、可維護、可交接的版本。備份 ZIP 是要保留這些真正有再利用價值的原始內容。

## 14. 這個作品的創新點在哪？

創新點不在單一技術，而在把 ODF 原始檔、文件生成、版本管理、評鑑完整度檢核與評鑑輸出整合成一個學生社團可理解、可落地的工作流程。

## 15. 後續可以怎麼擴充？

可以擴充更多文件類型、更多範本、不同學校規則、真正的 AI 文字整理、雲端同步與權限管理，也可以把 Projects 頁補成更完整的活動文件流管理。

## 16. 為什麼沒有先做 Google Drive 自動上傳？

因為這次 MVP 的核心目標是先把本機可用的文件流與 ODF / PDF / ZIP 流程做穩。若太早加入外部 API，會把重點從作品流程價值轉移到整合工程上。

## 17. 不使用 OpenAI API 是否影響作品價值？

不會。這個作品的主價值是 ODF 文件流、範本庫、版本管理、評鑑完整度與 ZIP 匯出。OpenAI API 只是未來可加值的文字整理能力，不是作品成立的前提。

## 18. 這跟單純提供範本下載有什麼差別？

單純下載範本只能解決「有空白檔可用」，但無法處理版本、文件狀態、評鑑缺漏、評鑑 ZIP 輸出。ODFlow 是把範本與後續管理、評鑑流程接起來。

## 19. 為什麼要支援七種文件類型？

現在已不只五種，而是七種核心文件類型，包含會議紀錄、開會通知單、會議議程、活動企劃書、活動成果報告、活動檢討會紀錄、年度計畫。這些已涵蓋學生社團最常見、最具代表性的日常行政與評鑑資料，也足以展示系統不是只做會議紀錄，而是具備多文件型態的可延伸架構。

## 20. 這個作品適合誰？

最直接的使用者是學生會、系學會與一般社團幹部。對學校行政單位來說，也能作為理解社團資料完整度與評鑑整理流程的一個展示型工具。

## 21. 你們的 ODF 範本真的能日常使用嗎？

核心範本現在已經不是只有測試格式。像會議紀錄、開會通知單、會議議程、活動企劃書、活動成果報告、活動檢討會紀錄、年度計畫與出席簽到表，都已升級成較正式的校園社團文件樣式，具備基本資料表、章節、清楚框線與可列印版面，足以作為日常社團行政文件起點。

## 23. 你們如何讓文件看起來不像程式隨便生成？

ODFlow 現在對會議紀錄、開會通知單、活動企劃書採用乾淨 ODT 樣板與 placeholder 填入。也就是先準備固定版型的 ODT 原始檔，再把 `content_json` 填入指定欄位，輸出的 ODT 會保留樣板的章節與表格結構。若樣板填入失敗，系統仍會 fallback 到 Task 14 的 generator，避免使用者無法匯出文件。

## 22. 為什麼不直接用 Word？

Word 當然能做文件，但這個作品想解決的不只是單一文件編輯，而是 ODF 原始檔保存、版本管理、評鑑完整度檢核、PDF 評鑑上傳包與 ODF 原始檔備份 ZIP 的整體流程。ODFlow 提供的是社團文件流，而不只是替代單一文書軟體。
