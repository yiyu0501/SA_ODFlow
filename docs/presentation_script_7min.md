# ODFlow 7 分鐘簡報逐字稿

## 0:00–0:40 開場與作品定位

各位評審好，我們的作品名稱是 ODFlow。  
ODFlow 是一套學生社團 ODF 文件流與評鑑整理系統，核心概念是讓社團在平時就能建立、保存和管理 ODF 原始檔，到了評鑑時，再把需要提交的資料整理成 PDF 評鑑上傳包。  
我們希望解決的，不只是文件生成，而是學生社團從日常行政到評鑑整理之間，長期缺少一條穩定文件流程的問題。

## 0:40–1:30 問題背景與痛點

學生社團平常一定會產生很多文件，像是會議紀錄、活動企劃書、成果報告、年度計畫、名冊、表單等等。  
但實際情況常常是，這些內容分散在不同人的電腦、Google Drive、聊天紀錄、Word、Excel 和 PDF 裡。  
等到評鑑前才開始整理，就會遇到幾個痛點。第一個是找不到原始檔，只剩 PDF。第二個是不知道哪些資料已經完成，哪些還缺。第三個是文件和評鑑分類之間沒有穩定對應。  
所以問題不是社團沒有文件，而是沒有一套可以平時累積、評鑑輸出的文件流。

## 1:30–2:30 ODFlow 解法

ODFlow 的解法，是把這整件事拆成幾個清楚的步驟。  
第一，使用者可以在 Generate 頁建立文件，目前已支援五種核心社團文件，包含會議紀錄、活動企劃書、活動成果報告、活動檢討會紀錄，以及年度計畫。  
第二，Files 頁負責版本管理、狀態管理，以及 ODT / PDF 匯出。  
第三，Dashboard 會顯示社團評鑑資料完整度，讓使用者知道哪些評鑑項目還缺資料。  
第四，Evaluation 頁可以依七大評鑑分類輸出 PDF 評鑑上傳包，另外也能輸出 ODF 原始檔備份 ZIP。  
第五，Templates 頁提供 22 個 ODT / ODS 範本，讓社團不只是最後轉檔，而是從一開始就用 ODF 建立內容。

## 2:30–4:40 系統 Demo 說明

接下來我用系統流程快速說明。  
首先，在 Settings 頁可以設定學年度、校區、社團名稱，這些資料會直接影響之後匯出的 ZIP 命名。系統也有示範資料功能，可以快速建立展示用的多種文件。  
接著到 Generate 頁。這裡可以選擇文件類型。會議紀錄支援貼上逐字稿或會議摘要，系統會先用 mock parser 產生草稿，再讓使用者手動編輯。其他像活動企劃書、活動成果報告、活動檢討會紀錄、年度計畫，則是直接用表單建立內容。  
產生完之後，文件會進到 Files 頁。Files 頁可以看到文件類型、版本、狀態、對應評鑑分類，並可以建立新版本。這裡也可以產生 ODT 和 PDF。這代表系統不是只停留在頁面資料，而是真的能把內容輸出成 ODF 原始檔和對外使用的 PDF。  
接著到 Dashboard。這裡會顯示整體社團評鑑資料完整度，以及七大評鑑項目的完成率，並提醒哪些文件還缺。這讓社團可以在平時就知道目前資料累積到什麼程度。  
最後到 Evaluation。這裡可以依照七大評鑑項目檢核缺漏，然後一鍵產生 PDF 評鑑上傳包，另外也能產生 ODF 原始檔備份 ZIP。也就是說，平時的文件累積最後會自然接到評鑑輸出，而不是評鑑前重新整理一次。

## 4:40–5:40 ODF 應用與競賽對應

這個作品對應 ODF 競賽學生組的重點，不只是因為它能輸出 ODT 或 ODS。  
更重要的是，ODFlow 讓 ODF 真的進入學生社團的行政流程。  
Templates 頁提供 22 個 ODT / ODS 範本，可以降低學生從 Word、Excel 轉向 ODF 的門檻。  
Generate 與 Files 讓 ODF 原始檔在平時就被建立和保存。  
Evaluation 則把這些平時累積的內容轉成評鑑需要的 PDF 評鑑上傳包。  
所以這個作品的 ODF 價值，在於把 ODF 從單純的檔案格式，變成一套日常使用、評鑑輸出的工作流程。

## 5:40–6:30 AI 使用說明與限制

關於 AI 的部分，我們這次是誠實處理。  
目前系統內沒有直接串接 OpenAI API。  
會議紀錄的文字整理流程，使用的是 mock parser，目的是提供一個可展示、可測試、可替換的最小流程。  
另外四種核心文件則是透過表單式生成，不依賴 OpenAI API，也能完成 ODF、PDF、ZIP 的完整流程。  
ODF / PDF / ZIP 匯出邏輯目前都由程式規則控制，不是交給 AI 自動決定。  
也就是說，AI 在這個版本裡是輔助性的，而不是作品價值的唯一來源。

## 6:30–7:00 未來推廣與結語

未來如果要推廣，ODFlow 可以往三個方向延伸。  
第一，是增加更多社團常用文件類型和範本。  
第二，是讓不同學校或不同評鑑規則可以調整分類邏輯。  
第三，是在保留人工確認和版本管理的前提下，再導入真正的 AI 文字整理能力。  
最後總結一下，ODFlow 想做的不是一個單次評鑑工具，而是一套讓學生社團平時就能保存 ODF 原始檔、管理文件、檢查缺漏，並在評鑑時自然輸出成果的流程系統。  
謝謝各位評審。
