# UI_SPEC_v18_ODFlow_direct_download_generate_form

## 修正範圍

本版基於 v17，只修三個問題：

1. 空白範本頁「下載範本」不要再跳到頁面上方才出現下載按鈕。
2. 空白範本卡片移除「查看說明」，只保留一個更明確的下載按鈕。
3. 生成文件 Step 2 改成可以填寫資料，Step 3 預覽必須跟著使用者填寫內容更新。

## 1. 空白範本直接下載

### 舊行為

點卡片上的「下載範本」後，頁面上方出現 Streamlit download button，需要再按一次。

### 新行為

卡片上的下載按鈕改為 HTML download link：

- 產生實際 ODT / ODS
- 轉為 data URI
- 直接在卡片按鈕上下載
- 不再顯示「查看說明」

### 按鈕樣式

- 單一按鈕
- 藍色漸層
- 較大高度
- 文字為「直接下載 ODT 範本」或「直接下載 ODS 範本」

## 2. 生成文件 Step 2：可填寫資料

Step 2 改成 HTML GET form。

欄位包含：

- 社團名稱
- 活動 / 文件名稱
- 日期
- 時間
- 地點
- 性質 / 類型
- 聯絡人
- 聯絡電話
- 電子信箱
- 指導老師
- 預算金額
- 活動 / 文件說明
- 備註

送出後進入 Step 3，所有欄位透過 query params 保留。

## 3. 生成文件 Step 3：動態預覽

Step 3 預覽不再固定為預設文字，而是讀取 Step 2 使用者填寫內容：

- 文件標題
- 社團名稱
- 日期
- 時間
- 地點
- 聯絡人
- 電話
- 說明
- 備註

## 4. 生成文件 Step 4：下載使用表單資料

Step 4 的 ODT 下載會使用 Step 2 / Step 3 的 query params 產生文件資料。

若文件類型支援正式 ODT 輸出，會透過既有 `generate_document_odt()` 產出 ODT；若失敗則退回範本下載。

## 限制

- 瀏覽器安全限制下，無法在「完全不點下載」的情況下強制寫入使用者硬碟。
- 本版改成「點卡片上的下載按鈕即下載」，不再需要跳到頁首再按第二次。
- PDF 仍保持尚未開放，不硬接假功能。
