# ODFlow AI 使用聲明比賽版

## 1. 開發過程中的 AI 使用情況

ODFlow 的開發過程有使用 AI 協助：

- 規劃產品結構與任務拆解
- 撰寫與整理部分程式碼
- 協助整理 README、展示文件與比賽說明素材

這些 AI 使用主要發生在開發與文件整理階段，目的是提升原型開發效率與文件一致性。

## 2. 目前系統內的 AI 功能現況

目前系統內沒有直接串接 OpenAI API。  
現有的「文字／逐字稿轉會議紀錄」流程使用的是 `ai/mock_parser.py`，用來展示可替換、可測試的最小流程，而不是宣稱已具備真正大型語言模型服務。

## 3. 系統不依賴 OpenAI API 也能完成的流程

ODFlow 目前已可在不依賴 OpenAI API 的情況下完成以下流程：

- 透過表單式建立多種文件
- 產生與保存 ODF 原始檔
- 匯出 PDF
- 進行版本管理與狀態管理
- 檢查社團評鑑資料完整度
- 輸出 PDF 評鑑上傳包
- 輸出 ODF 原始檔備份 ZIP

也就是說，作品的核心價值不建立在外部 AI API 是否接入，而是建立在 ODF 文件流與評鑑整理流程。

## 4. ODF / PDF / ZIP 輸出機制

目前 ODF / PDF / ZIP 的輸出皆由程式規則與既有 generator 產生，不是由 AI 任意決定內容或輸出格式。  
這代表系統的檔案輸出邏輯是可預期、可驗證、可維護的。

## 5. 未來若導入 OpenAI API 的原則

若未來導入 OpenAI API，預計只限定在：

- 會議文字整理
- 文件草稿生成

不會把版本管理、ODF / PDF / ZIP 輸出規則完全交給 AI 自由決定。

## 6. 人工編輯、確認與版本管理

ODFlow 目前保留人工介入機制，包含：

- 使用者可編輯草稿內容
- 使用者可儲存新版本
- 使用者可調整文件狀態
- 使用者可決定哪個版本作為目前正式版本

這樣的設計是為了確保系統生成內容仍受到人類確認與管理，而不是直接自動發布。

## 7. 使用者可辨識的內容來源

系統設計上，使用者可以清楚知道：

- 哪些內容是系統先產出的草稿
- 哪些內容是使用者後續編輯與修正
- 哪個版本目前被設定為正式版

這有助於保留透明度，也符合展示型 MVP 在 AI 使用上的誠實原則。
