# ODFlow v0.3 範圍決策

這份文件用馬斯克五步工作法整理 v0.3 的取捨，目的是避免版本失焦。

## 第一步：質疑需求

### 真的必要的功能

1. 讓評審與一般使用者一眼看懂 ODFlow 的主要流程
2. 讓核心文件輸出看起來更像正式社團文件
3. 讓空白範本下載與建立文件流程更直覺
4. 讓 Dashboard 與社團評鑑頁更容易理解
5. 保留目前不依賴 OpenAI 的完整 ODF / PDF / ZIP 流程

### 看起來很厲害，但目前不必要的功能

1. OpenAI API 自動理解各種複雜文字
2. 音檔自動轉逐字稿
3. Google Drive 自動上傳與同步
4. 完整 Projects 專案管理
5. 把 22 個範本全部一次精修到高保真正式版
6. 炫技型圖表或大型前端重構

## 第二步：刪除

v0.3 明確先刪掉下列衝動，避免功能膨脹：

1. OpenAI API 暫不做
2. 音檔轉文字暫不做
3. Google Drive 自動上傳暫不做
4. Projects 完整專案管理暫不做
5. 全部 22 個範本高品質精修暫不做

這些方向不是沒價值，而是和 v0.3 的主要問題不成正比，現在做只會分散資源。

## 第三步：簡化與優化

v0.3 真正該做的是簡化操作與提升可讀性：

1. 中文側邊欄
2. 範本頁 UX 重整
3. Dashboard 進度條與資訊層級重整
4. 社團評鑑 ZIP 匯出前後的摘要與預覽
5. 核心範本精修
6. 首頁流程導覽
7. Projects 頁明確標示未來擴充

## 第四步：加速循環

ODFlow 的展示價值，本質上來自「少按幾步就能拿到正式文件或上傳包」。

因此 v0.3 要保留並強化這些一鍵流程：

1. 一鍵建立示範資料
2. 一鍵產生 ODT / PDF
3. 一鍵下載空白範本
4. 一鍵產生 PDF 評鑑上傳包
5. 一鍵產生 ODF 原始檔備份 ZIP

如果某個改動無法讓這些主流程更清楚、更快、更穩，就不該列為 v0.3 主工作。

## 第五步：自動化

真正的高自動化方向，放到後續版本：

1. AI parser
2. 音檔轉文字
3. Google Drive 上傳
4. 雲端同步
5. 更進階的文件規則推薦

v0.3 先把規則式流程做穩，之後再往 AI 與自動化推進，風險較低。

## 結論

v0.3 的核心不是加更多功能，而是把現有主線做得更像成品：

1. 文件更正式
2. 操作更直覺
3. 展示更容易懂
4. 評審更看得出 ODF 的流程價值
