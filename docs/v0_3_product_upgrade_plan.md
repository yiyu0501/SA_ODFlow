# ODFlow v0.3 產品品質升級規劃

## v0.3 版本目標

ODFlow v0.3 的定位是「範本品質與展示體驗升級版」。

這一版不追求再擴大功能邊界，而是把目前已經能跑通的生成、匯出、評鑑整理流程，提升到更接近日常可用、評審能快速理解、輸出文件更像正式校園社團文件的品質。

## 目前版本問題盤點

1. 範本內容雖可用，但格式仍偏工程產物，和真實校園行政文件有落差。
2. ODT / ODS 產出格式尚未明確對齊台灣校園文件習慣，例如字體、標題、欄位排法、表格清晰度。
3. 範本頁目前同時承擔空白範本下載與建立文件入口，但操作心智模型還不夠清楚。
4. Streamlit 介面仍偏工程感，首頁、Dashboard、社團評鑑頁的視覺引導不夠強。
5. 側邊欄與頁面命名仍有英文痕跡，對非技術評審不夠直覺。
6. Dashboard 與社團評鑑頁雖已有資料，但視覺呈現還不夠有層次。
7. Projects 頁目前不是核心價值，若繼續投入完整專案管理，會稀釋 v0.3 的重點。

## 必須保留的核心功能

v0.3 必須保留並延續以下能力，不能因為展示整理而破壞：

1. 五種文件類型生成流程
2. Files 文件庫與版本管理
3. ODT / PDF 匯出
4. PDF 評鑑上傳包 ZIP
5. ODF 原始檔備份 ZIP
6. Dashboard 社團評鑑資料完整度
7. Evaluation 缺漏文件檢核
8. 22 個空白範本與 5 個核心範本建立文件流程
9. Settings 與 Demo Data

## 暫時不做的功能

v0.3 明確不處理以下方向：

1. OpenAI API 串接
2. 音檔轉文字
3. Google Drive 自動上傳
4. 雲端同步
5. 登入系統與多使用者權限
6. Projects 完整專案管理
7. 資料庫 schema 重構
8. ODT / PDF 產生器大重寫
9. 全部 22 個範本逐一做高保真排版

## 需要優先改善的功能

### P0：展示可理解度

1. 側邊欄中文化
2. 首頁加入清楚的流程導引
3. Dashboard 改成更容易看懂的完整度視覺化
4. 社團評鑑頁補強匯出摘要與 ZIP 結果預覽

### P1：範本品質

1. 精修核心 ODT 範本
2. 精修核心文件生成後的 ODT / PDF 視覺格式
3. 讓空白範本和「使用此範本建立文件」入口更清楚分流

### P2：非核心頁面降噪

1. Projects 頁明確標示未來擴充
2. 避免 UI 同時傳達太多尚未完成的方向

## 使用者操作流程調整建議

建議把主要操作流程整理成以下路徑：

1. 先到社團設定填基本資料
2. 需要展示時一鍵建立示範資料
3. 日常使用時可從兩條路進入：
   - 到生成文件頁直接建立文件
   - 到空白範本頁下載空白範本，或從核心範本建立文件
4. 到檔案庫檢查版本、產出 ODF 原始檔與 PDF
5. 到儀表板查看社團評鑑資料完整度
6. 到社團評鑑頁輸出 PDF 評鑑上傳包與 ODF 原始檔備份 ZIP

這個流程比目前更適合展示，也更接近真實社團日常使用方式。

## UI / UX 改善方向

1. 頁面名稱全面中文化，降低評審理解成本。
2. 首頁改成導覽型首頁，不只放說明文字，而是清楚展示「設定 -> 建立文件 -> 管理 -> 評鑑輸出」流程。
3. 每個核心頁面都要有一句話定位，避免使用者不知道這頁是做什麼。
4. 按鈕文案統一使用目前產品用語，例如「ODFlow」「ODF 原始檔」「PDF 評鑑上傳包」。
5. 範本頁要把「下載空白範本」和「使用範本建立文件」視覺上拆開。
6. 非核心頁面降低視覺權重，避免搶走生成、檔案庫、評鑑輸出的主線。

## Dashboard 視覺化規劃

建議保留 Streamlit 內建元件，不做大型前端重構，但把資訊層級重新整理：

1. 頂部顯示整體社團評鑑資料完整度
2. 七大類別改成卡片或進度列，直接顯示完成率與配分權重
3. 已完成、進行中、缺漏文件數分開顯示
4. 最近文件與下一步建議保留，但排版需更像操作導引
5. 缺漏最多的類別要有明顯提示

## 社團評鑑頁視覺化規劃

1. 缺漏文件清單和已完成文件清單分開顯示
2. 匯出 PDF 評鑑上傳包前，先顯示本次預計輸出的文件摘要
3. 匯出完成後顯示：
   - 成功輸出數
   - 未輸出數
   - 涵蓋哪些評鑑分類
   - ZIP 檔名
4. 強化「本機 ZIP 下載」說明，避免誤會成雲端自動上傳

## Templates 頁重構規劃

目前 Templates 頁已具備功能，但心智模型不夠乾淨。v0.3 建議重構為三層：

1. 頁首先說明這是「ODFlow 空白範本與核心範本入口」
2. 第一層先區分三大類：
   - 日常行政型
   - 專案活動型
   - 社團評鑑型
3. 每個範本卡片明確分成兩種操作：
   - 下載空白範本
   - 使用此範本建立文件

其中只有 5 個核心 ODT 範本要進入建立文件流程，其餘範本維持空白範本定位即可。

## 風險

1. 若一次想把 22 個範本都做成高品質正式版，範圍會失控。
2. ODT / ODS 排版在 LibreOffice、OnlyOffice、Google Sheets 間可能仍有細部差異。
3. 若 UI 改動太大，容易演變成前端重構，偏離本次升級目標。
4. 若 Projects 頁不弱化，評審可能誤以為那是主產品，分散作品焦點。

## 驗收標準

v0.3 可視為達標，至少要符合：

1. 側邊欄與主要頁面名稱全面中文化
2. 首頁、Dashboard、社團評鑑頁的展示動線更明確
3. Templates 頁可清楚分辨空白範本下載與建立文件入口
4. 核心範本與核心文件輸出格式比目前更接近正式校園文件
5. 不依賴 OpenAI API，仍可完成文件生成、ODF / PDF 匯出與評鑑 ZIP 流程
6. Projects 頁明確標示為未來擴充，不再誤導為目前主功能
