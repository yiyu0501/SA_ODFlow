# ODFlow 範本規格書：簽到表

## 一、範本基本資料

範本名稱：簽到表
別名：活動簽到表、會議簽到表、社課簽到表
template key：attendance_sheet
格式：ODT
分類：日常行政型
重要性：高
是否保留：保留，核心範本
是否支援空白範本下載：支援
是否支援使用此範本建立文件：支援

本範本用途為協助學生社團、學生自治組織或活動承辦人快速製作可列印的簽到表，適用於社課、會議、講座、工作坊、活動報到與一般社團聚會。

ODFlow 的簽到表應以一般社團最常見的現場操作情境為主：
活動當天列印一張 A4 紙，放在報到處或會議現場，讓參與者自行填寫系級或單位與姓名。

---

## 二、設計定位

簽到表 v1 採「通用雙欄空白簽到表」設計。

本範本不採固定名單式簽到表。
也就是說，預設不會先列出特定人員姓名、職稱或分組。

設計理由：

1. 一般社團活動不一定事前知道所有出席者。
2. 現場簽到通常只需要讓參與者自行填寫系級與姓名。
3. 固定名單式簽到表需要匯入社員名冊、幹部名冊或出席名單，屬於後續進階功能。
4. 通用雙欄設計較符合一般社團實際列印與使用情境。
5. 不額外設置簽名欄，避免表格過寬、過擠，也避免一張簽到表只能容納很少人。

---

## 三、設計目標

簽到表應達成以下目標：

1. 能快速產生一般社團可直接列印使用的簽到表。
2. 能清楚顯示活動或會議名稱。
3. 能清楚顯示日期、時間、地點與主辦單位。
4. 採雙欄表格，增加單頁可容納人數。
5. 每列提供系級或單位與姓名欄位。
6. 使用者可自行設定空白列數。
7. 文件應簡潔、清楚、可印，不應過度複雜。
8. 文件打開後應像正式簽到表，而不是範本說明頁。

---

## 四、文件標題

### 1. 標題格式

標題建議置中顯示。

第一行：

{{school_name}} {{club_name}}

第二行：

「{{event_name}}」簽到表

範例：

臺北市立大學 傑青社
「期初社員大會」簽到表

或：

臺北市立大學 傑青社
「社課活動」簽到表

若不需要學校名稱，也可使用：

{{club_name}}
「{{event_name}}」簽到表

## 五、頁首、頁尾與版面

### 1. 版面方向

簽到表預設使用 A4 直式。

原因：

1. 一般印表機最常使用 A4 直式。
2. 活動現場拿取、傳遞與歸檔較方便。
3. 雙欄設計已可提高單頁容納人數，不必改成橫式。

---

### 2. 字型與字級

整份 ODT 文件以標楷體為主要字型。

建議設定：

* 第一行標題：標楷體，18 pt，粗體，置中
* 第二行標題：標楷體，16 或 18 pt，粗體，置中
* 基本資料文字：標楷體，12 pt
* 表格欄位標題：標楷體，12 pt，粗體
* 表格內容列：標楷體，12 pt
* 頁尾頁碼：標楷體，10 或 11 pt

注意：repo 不應放入字型檔。ODT 可指定使用標楷體，實際顯示依使用者電腦或轉檔環境是否具備該字型而定。

---

### 3. 頁尾頁碼

簽到表如超過一頁，文件每頁頁尾應有頁碼。

建議格式：

第 1 頁／共 2 頁

或：

第 1 頁 共 2 頁

頁碼置中，字級建議 10 或 11 pt。

若只有一頁，也可顯示：

第 1 頁 共 1 頁

---

## 六、文件整體結構

簽到表正式版型順序如下：

1. 兩行置中標題
2. 基本資料區
3. 雙欄簽到表格
4. 備註區，選填
5. 頁尾頁碼

---

## 七、基本資料區

簽到表上方應提供活動或會議基本資料。

建議欄位：

* 日期與時間
* 活動地點
* 活動名稱
* 主辦單位

版型建議：

日期與時間：{{event_date}} {{start_time}} 至 {{end_time}}
活動地點：{{location}}
活動名稱：{{event_name}}
主辦單位：{{organizer}}

說明：

1. 日期與時間應允許使用者自行輸入或修改。
2. 活動地點可為教室、會議室、活動場地或線上會議。
3. 活動名稱應與標題中的 event_name 一致。
4. 主辦單位可填社團名稱、組別或共同主辦單位。
5. 若某欄無資料，可留白或填「無」。

---

## 八、簽到表格設計

### 1. 採雙欄設計

簽到表 v1 採雙欄設計。

雙欄設計格式如下：

| 系級／單位 | 姓名 | 系級／單位 | 姓名 |
| ----- | -- | ----- | -- |
|       |    |       |    |
|       |    |       |    |
|       |    |       |    |

設計理由：

1. 一般社團活動簽到人數不一定很多。
2. 若採單欄且加入過多欄位，容易浪費版面。
3. 雙欄能讓一頁 A4 容納更多簽到空格。
4. 實務上參與者通常只需要填系級或單位與姓名。
5. 不另外加簽名欄，避免表格過度擁擠。

---

### 2. 不額外設置簽名欄

簽到表 v1 不另外設置「簽名」欄。

原因：

1. 一般社團活動中，姓名欄通常即可作為現場簽到依據。
2. 若同時放「姓名」與「簽名」，雙欄版面會過於擁擠。
3. 若改成單欄來容納簽名，單頁可容納人數會大幅下降，實務上不方便。
4. 本範本優先服務一般社團活動與社課簽到，而非正式固定名單出席確認。

若特定組織需要正式簽名欄，可由未來進階範本或名冊式簽到表處理。

---

### 3. 欄位名稱

預設欄位：

* 系級／單位
* 姓名

欄位說明：

系級／單位：
可填系級、班級、單位、組別、職稱或所屬團隊。

姓名：
由參與者現場手寫姓名，作為簽到依據。

---

### 4. 空白列數

使用者應可設定預計人數或空白列數。

建議欄位：

* 預計人數
* 每頁列數
* 是否自動補滿雙欄

系統行為建議：

1. 若使用者輸入預計人數 30 人，系統應產生至少 30 個簽到位置。
2. 雙欄表格每一列可容納 2 人。
3. 若預計人數為奇數，最後一格可留白。
4. 若人數超過一頁容量，系統應自動延伸到下一頁。
5. 空白範本下載可預設提供約 30 至 40 個簽到位置。

---

## 九、備註區

簽到表下方可保留簡短備註區。

欄位名稱：

備註

用途：

記錄簽到注意事項、請假說明、活動特殊規則或現場補充。

範例：

備註：請參與者依序填寫系級與姓名。

若無備註，可不顯示或留白。

---

## 十、固定名單式簽到表暫不納入 v1

學生議會或學生自治組織可能需要固定名單式簽到表，例如事前列出姓名、職稱、簽名與備註，並依學院、部門或組織分組。

此類簽到表暫不納入簽到表 v1 核心範本。

原因：

1. 固定名單式簽到表需要事前名冊資料。
2. 可能需要姓名、職稱、所屬單位、分組、排序等欄位。
3. 可能需要從社員名冊、幹部名冊或出席名單匯入資料。
4. 實作範圍較大，容易偏離一般社團的通用需求。
5. v1 應先提供一般社團最常使用的簡單簽到表。

未來可另設進階功能：

固定名單簽到表
或
名冊式簽到表

未來功能方向：

從社員名冊、幹部名冊或活動出席名單匯入資料，自動產生含姓名、職稱、簽名、備註與分組標題的簽到表。

---

## 十一、空白範本下載要求

下載的空白 ODT 應是可直接列印使用的正式簽到表。

空白範本應至少預留：

1. 兩行置中標題
2. 日期與時間
3. 活動地點
4. 活動名稱
5. 主辦單位
6. 雙欄簽到表格
7. 備註區，選填
8. 頁尾頁碼

空白範本預設應提供足夠的空白簽到列，例如 30 至 40 個簽到位置。

---

## 十二、空白範本不得出現的內容

正式下載的空白 ODT 文件本體，不得出現 metadata 型說明文字。

禁止出現在文件本體中的文字包括：

* 範本類型
* 建議格式
* 對應評鑑分類
* 使用情境
* 使用說明

這些文字可以出現在 ODFlow 網頁上的範本卡片說明，但不能出現在正式下載的空白文件內容中。

---

## 十三、空白範本中心預覽要求

空白範本中心的簽到表預覽應呈現正式可列印表格，而不是 metadata 清單。

預覽應包含：

1. 兩行置中標題
2. 日期與時間
3. 活動地點
4. 活動名稱
5. 主辦單位
6. 雙欄簽到表格
7. 頁碼

預覽中不得出現：

* 範本類型
* 建議格式
* 對應評鑑分類
* 使用情境
* 使用說明

---

## 十四、使用者填寫欄位

ODFlow 的「使用此範本建立文件」功能，至少應提供以下欄位。

### 1. 基本資料

* 學校名稱
* 社團名稱
* 活動或會議名稱
* 日期
* 開始時間
* 結束時間
* 活動地點
* 主辦單位
* 備註

### 2. 表格設定

* 預計人數
* 空白列數
* 是否自動補滿雙欄
* 是否產生第二頁

### 3. 版型設定

v1 預設版型：

雙欄通用簽到表

暫不提供固定名單式簽到表作為 v1 核心功能。

## 十七、驗收標準

此範本完成後，應符合以下驗收標準：

1. 下載的 ODT 是正式簽到表，不是 metadata 說明頁。
2. 文件標題採兩行置中。
3. 文件主要字型指定為標楷體。
4. 內文字級為 12 pt。
5. 文件包含日期與時間。
6. 文件包含活動地點。
7. 文件包含活動名稱。
8. 文件包含主辦單位。
9. 文件採雙欄簽到表格。
10. 每個簽到位置包含系級／單位與姓名。
11. 預設不加入簽名欄。
12. 預設不加入固定名單。
13. 使用者可設定預計人數或空白列數。
14. 若人數超過單頁容量，系統可延伸到下一頁。
15. 預覽畫面像正式可列印簽到表。
16. 文件本體不得出現「範本類型、建議格式、對應評鑑分類、使用情境、使用說明」等 metadata 型文字。
17. 不得把字型檔 commit 進 repo。
18. 原本 ODT / PDF 匯出功能不得被破壞。

## 十八、優先級與原因

優先級：高

原因：

1. 簽到表是社團活動、會議與社課最常使用的文件之一。
2. 簽到表常作為社團評鑑與活動成果佐證資料。
3. 雙欄設計符合一般社團現場列印與簽到實務。
4. 不做固定名單版，可避免 v1 範圍過度膨脹。
5. 本範本能補足社團活動與會議的基本行政文件需求。
