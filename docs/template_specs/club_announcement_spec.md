# ODFlow 範本規格書：社團公告／通知

## 一、範本基本資料

範本名稱：社團公告／通知
常見別名：社團公告、社團通知、社員通知、活動通知、一般通知、行政公告、社團事項公告
template key：club_announcement
格式：ODT
分類：日常行政型
重要性：中高
是否保留：保留，核心範本
是否支援空白範本下載：支援
是否支援使用此範本建立文件：支援

本範本用於學生社團發布一般行政通知、活動公告、社員提醒、繳費通知、報名通知、資料繳交通知、社課通知、招募公告或其他非會議類正式通知。

本範本 v1 的核心原則是：

1. 使用 ODT，不使用 ODS。
2. 本範本是一般社團公告，不是開會通知單。
3. 文件應簡潔、正式、可直接給社員或校內單位閱讀。
4. 支援公告對象、公告主旨、公告內容、重要日期、聯絡方式與附件。
5. 不做成社群貼文文案，而是正式文件版公告。
6. 可作為社團日常行政、活動通知與評鑑資料佐證。
7. 文件打開後應像正式社團公告，而不是範本說明頁。

---

## 二、範本定位

社團公告／通知是社團對社員、幹部、校內學生或合作單位發布訊息的正式文件。

它主要回答以下問題：

1. 這份公告要通知誰？
2. 公告主旨是什麼？
3. 需要對方知道什麼？
4. 有什麼重要日期、時間或地點？
5. 對方需要採取什麼行動？
6. 有沒有附件？
7. 有問題要找誰？

---

## 三、與其他範本的區別

### 1. 與開會通知單的區別

開會通知單專門用於正式會議。

開會通知單重點是：

* 開會事由
* 開會時間
* 開會地點
* 主持人
* 出席者
* 列席者
* 附件

社團公告／通知重點是：

* 一般公告事項
* 活動通知
* 社員提醒
* 報名或繳費通知
* 行政事項通知

因此兩者應分開，不應混成同一份範本。

---

### 2. 與活動企畫書的區別

活動企畫書是活動規劃文件。

社團公告／通知只是把活動資訊通知給對象。

活動企畫書重點是完整規劃；社團公告／通知重點是清楚傳達。

---

### 3. 與社群貼文的區別

社群貼文可以活潑、有行銷語氣。

社團公告／通知應較正式，適合：

* 上傳雲端
* 寄信
* 貼在群組
* 作為活動行政資料
* 作為評鑑佐證

## 六、頁面與版面原則

### 1. 紙張與頁面

建議設定：

* 紙張：A4
* 方向：直式
* 頁數：通常 1 頁，可自然延伸
* 主要字型：標楷體
* 頁尾頁碼：若超過 1 頁，建議保留

### 2. 字型與字級

建議設定：

* 第一行標題：標楷體，18 pt，粗體，置中
* 第二行標題：標楷體，16 pt，粗體，置中
* 區塊標題：標楷體，14 pt，粗體
* 內文：標楷體，12 pt
* 表格文字：標楷體，12 pt
* 頁尾頁碼：標楷體，10 或 11 pt

注意：repo 不應放入字型檔。ODT 可指定使用標楷體，實際顯示依使用者電腦或轉檔環境是否具備該字型而定。

## 十、公告主旨

欄位名稱：

公告主旨

用途：

簡短說明本公告要通知的重點。

範例：

* 期初社員大會報名開始
* 社費繳交通知
* 社課時間異動通知
* 淨山活動行前通知
* 幹部招募公告
* 社團評鑑資料補交通知
* 活動取消通知

規則：

1. 主旨應簡短明確。
2. 建議 30 字內。
3. 不宜寫成過長段落。
4. 若是活動通知，主旨應包含活動名稱。

---

## 十一、公告內容

公告內容是本範本核心。

建議格式：

一、公告事項
二、詳細說明
三、注意事項

### 1. 公告事項

用途：

用一句話說明本公告重點。

範例：

本社將於 114 學年度第 1 學期辦理期初社員大會，請有意參與之社員於期限內完成報名。

---

### 2. 詳細說明

用途：

補充公告背景、活動內容、行政事項或需要知道的資訊。

可用段落或條列式。

範例：

1. 本次活動將說明本學期社團活動規劃。
2. 活動當日將進行社員資料確認。
3. 請參與者準時到場，並攜帶學生證。
4. 若無法出席，請提前告知活動負責人。

---

### 3. 注意事項

用途：

提醒重要限制、期限或風險。

範例：

* 報名截止後恕不受理現場報名。
* 若活動因天候因素異動，將另行公告。
* 請參與者自行確認交通與保險事項。
* 活動照片可能作為成果報告與評鑑資料使用。

---

## 十二、重要日期與時間

若公告涉及活動、報名、繳費或資料繳交，應列出重要時間。

建議表格：

| 項目 | 日期 | 時間 | 地點／方式 | 備註 |
| -- | -- | -- | ----- | -- |

範例：

| 項目     | 日期         | 時間          | 地點／方式     | 備註     |
| ------ | ---------- | ----------- | --------- | ------ |
| 報名截止   | 2026/09/15 | 23:59       | Google 表單 | 逾期不受理  |
| 活動日期   | 2026/09/20 | 12:10-13:00 | 活動中心      | 請準時到場  |
| 社費繳交期限 | 2026/09/25 | 23:59       | 轉帳或現金     | 轉帳後請回報 |

若無重要日期，可填「無」。

---

## 十三、需要辦理事項

此區用於告訴公告對象需要採取什麼行動。

建議表格：

| 辦理事項 | 對象 | 截止時間 | 辦理方式 | 備註 |
| ---- | -- | ---- | ---- | -- |

範例：

| 辦理事項   | 對象     | 截止時間       | 辦理方式      | 備註 |
| ------ | ------ | ---------- | --------- | -- |
| 填寫報名表  | 有意參與社員 | 2026/09/15 | Google 表單 |    |
| 繳交社費   | 全體社員   | 2026/09/25 | 現金或轉帳     |    |
| 回覆出席狀況 | 幹部     | 2026/09/18 | LINE 群組   |    |
| 補交資料   | 活動工作人員 | 2026/09/20 | Email     |    |

若只是單純公告，可填「無」。

---

## 十四、聯絡方式

聯絡方式用於讓公告對象知道有問題要找誰。

建議欄位：

* 聯絡人
* 職稱／組別
* 電話
* Email
* 其他聯絡方式

建議表格：

| 聯絡人 | 職稱／組別 | 聯絡方式 | 備註 |
| --- | ----- | ---- | -- |

範例：

| 聯絡人 | 職稱／組別 | 聯絡方式                                                    | 備註      |
| --- | ----- | ------------------------------------------------------- | ------- |
| 王小明 | 活動負責人 | [example@utaipei.edu.tw](mailto:example@utaipei.edu.tw) |         |
| 李小華 | 財務    | LINE ID: example                                        | 社費問題請聯絡 |

規則：

1. 若公告對外公開，應避免放過多個人電話。
2. 可優先使用 Email 或社團官方帳號。
3. 若放個人聯絡方式，應確認當事人同意。

---

## 十五、附件清單

附件不得只寫「附件一、附件二、附件三」，應寫出具體名稱。

建議格式：

* 附件一：期初社員大會報名表連結
* 附件二：活動流程表
* 附件三：社費繳交通知與轉帳資訊
* 附件四：活動行前通知單
* 附件五：資料補交清單

若無附件，應填：

附件：無

## 十七、備註

備註區用於放置補充說明。

範例：

* 本公告若有更新，將以社團群組最新公告為準。
* 若報名人數超過上限，將依報名順序錄取。
* 活動相關資料將作為社團成果報告與評鑑資料使用。
* 若有特殊需求，請提前聯絡承辦人。

若無備註，可填「無」。

## 二十一、公告狀態

公告狀態主要作為 ODFlow 專案層資料，不一定出現在正式 ODT 本體。

建議狀態：

* 草稿
* 待確認
* 已發布
* 已更新
* 已取消

用途：

1. 追蹤公告是否已完成。
2. 區分公告草稿與正式公告。
3. 未來可提醒公告是否需要更新。
4. 可串接社團通知紀錄。

正式空白 ODT 本體不應出現「草稿、待確認、已發布」等系統流程欄位，除非使用者在生成文件時選擇輸出。

---

## 二十二、空白範本下載要求

下載的空白 ODT 應是正式社團公告／通知，不是 metadata 說明頁。

空白範本應至少包含：

1. 文件標題
2. 公告基本資料
3. 公告對象
4. 公告主旨
5. 公告內容
6. 重要日期與時間
7. 需要辦理事項
8. 聯絡方式
9. 附件清單
10. 發布單位與發布日期
11. 備註
12. 頁尾頁碼

空白 ODT 本體不得出現網頁 UI 操作文字，例如：

* 新增公告事項
* 匯入社員名冊
* 匯入活動企畫書
* 自動發布通知
* 自動產生評鑑 ZIP

這些文字可以出現在 ODFlow 生成文件頁或專案頁，但不能出現在正式空白文件本體。

---

## 二十三、空白範本不得出現的內容

正式下載的空白 ODT 文件本體，不得出現 metadata 型說明文字。

禁止出現在文件本體中的文字包括：

* 範本類型
* 建議格式
* 對應評鑑分類
* 使用情境
* 使用說明
* 系統自動化說明
* 專案管理說明
* 新增公告事項
* 匯入社員名冊
* 匯入活動企畫書
* 自動發布通知
* 自動產生評鑑 ZIP

這些文字可以出現在 ODFlow 網頁上的範本卡片說明、生成文件頁或專案頁，但不能出現在正式下載的空白文件內容中。

---

## 二十七、驗收標準

此範本完成後，應符合以下驗收標準：

1. 下載的 ODT 是正式社團公告／通知，不是 metadata 說明頁。
2. 範本使用 ODT。
3. 範本應與開會通知單分開，不得混成會議通知。
4. 文件標題包含學校名稱、社團名稱、公告類型與公告主旨。
5. 文件包含公告基本資料。
6. 文件包含公告對象。
7. 文件包含公告主旨。
8. 文件包含公告內容。
9. 文件包含重要日期與時間。
10. 文件包含需要辦理事項。
11. 文件包含聯絡方式。
12. 文件包含附件清單。
13. 附件清單不得只寫附件一、附件二、附件三，應顯示具體附件名稱。
14. 文件包含發布單位與發布日期。
15. 生成文件頁應支援新增多筆重要日期與時間。
16. 生成文件頁應支援新增多筆需要辦理事項。
17. 生成文件頁應支援新增多筆附件。
18. 未來應能從活動企畫書、活動申請表、活動流程表、工作分配表與社員名冊帶入資料。
19. 空白 ODT 本體不得出現「新增公告事項、匯入社員名冊、匯入活動企畫書、自動發布通知、自動產生評鑑 ZIP」等 UI 或系統操作文字。
20. 文件本體不得出現「範本類型、建議格式、對應評鑑分類、使用情境、使用說明」等 metadata 型文字。
21. 不得把字型檔 commit 進 repo。
22. 原本 ODT / PDF 匯出功能不得被破壞。

## 二十八、優先級與原因

優先級：中高

原因：

1. 社團公告／通知是日常行政中常見且實用的文件。
2. 本範本可補足開會通知單只適用會議的限制。
3. 本範本可用於活動公告、社課通知、繳費提醒、行前通知與行政事項公告。
4. 本範本可協助社團保留正式通知紀錄。
5. 本範本可與活動企畫書、活動流程表、社員名冊與評鑑 ZIP 串接。
6. 本範本能讓社團日常溝通不只停留在聊天紀錄，而是形成可歸檔的正式文件。
